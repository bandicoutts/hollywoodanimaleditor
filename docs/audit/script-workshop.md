# Audit: Script Workshop Tab

**Date:** 2026-04-28  
**Audited against:** `1.json` (save file), `TagData.json`, game element data

---

## How It Works

The Script Workshop is a **read-only** suggestion and builder tool. It reads several save fields to determine which story elements are available to the player, then generates scored script combinations. Nothing is written back to the save file.

### Save-file fields read (none written)

| Field | Type | Purpose |
|---|---|---|
| `tagPool` | `TagPoolEntry[]` | Source of truth for unlocked elements — only IDs in this array are available |
| `tagRecipesPool` | `string[]` | Fallback for recipe-discovered elements not yet in `tagPool` |
| `openedPerks` | `string[]` | Read to calculate `contentTagBudget` via `TAGS_SLOTS_6`–`TAGS_SLOTS_10` perks |
| `timePassed` | `string` | Game date (`"DAYS.HH:MM:SS"`) used to evaluate time-gated unlock conditions |
| `joinedAssociation` | `boolean` (optional) | Initialises the "Exclude Banned" toggle |
| `currentTagsInCodex` | `Record<string, {...}>` | Keys are banned element IDs (alliance-set) |
| `queueTagsForCodex` | `Record<string, {...}>` | Keys are pending-ban element IDs |

### What it produces
Two modes:
- **Generate:** Scores all possible combos from the player's unlocked pool, returns top results sorted by chosen bias (Art / Commercial / Balanced / Pollux)
- **Builder:** Step-by-step interactive script assembly with budget enforcement and compatibility scoring

### Scoring
| Component | Formula |
|---|---|
| Art | Sum of all element `art` values + genre-pair bonus |
| Commercial | Sum of all element `com` values + genre-pair bonus |
| Synergy | Pairwise compatibility scores (perfect = 1.0, strong = 0.5) |
| Pollux | `genreFactor × (art × 2 + com)` |

### Content tag budget
Base: 5 slots (2 fixed: protagonist + finale). Each `TAGS_SLOTS_6`–`TAGS_SLOTS_10` perk adds 1, up to 10 total. Builder enforces this limit at selection time.

---

## What Works Correctly

### Read-only — no write risk — ✓
The module touches no save fields. A player can use the Workshop on any save without risk of corruption.

### `tagPool` as unlock source — ✓
The module correctly treats `tagPool` membership (plus `tagRecipesPool` fallback) as the sole unlock gate, rather than re-evaluating unlock dates independently.

### Alliance/codex filtering — ✓
`currentTagsInCodex` keys are shown as "Banned" (red badge), `queueTagsForCodex` keys as "Pending Ban" (gold badge), regardless of filter state. When "Exclude Banned" is on, banned elements are removed from the generation pool. This matches the in-game Alliance mechanic.

### `timePassed` date parsing — ✓
Format `"DAYS.HH:MM:SS"` (e.g. `"3287.00:00:00"`) is correctly parsed to an absolute game date used for evaluating time-gated elements. Falls back to inferring game date from `tagPool` entry dates.

### Content budget enforcement — ✓
Builder correctly allocates 2 fixed slots and enforces the variable max from perks.

## Issues and Discrepancies

### 1. Musical and Slapstick Comedy have no Pollux factor — score to zero

`POLLUX_GENRE_FACTORS` defines weights for 10 genres:
```
DRAMA: 1.0, ROMANCE: 0.9, COMEDY: 0.8, DETECTIVE: 0.8, ADVENTURE: 0.8,
ACTION: 0.7, THRILLER: 0.6, SCIENCE_FICTION: 0.5, HISTORICAL: 0.5, HORROR: 0.3
```

`MUSICAL` and `SLAPSTICK_COMEDY` are absent. When either is selected as primary genre, the Pollux score will be `0 × (art × 2 + com) = 0`. Scripts using these genres will always rank last under Pollux bias, regardless of their actual content quality.

Whether Pollux is actually unavailable for Musical/Slapstick films in-game is unconfirmed. If the award is available for those genres, the editor misleads players by showing zero Pollux potential.

**Recommendation:** Research whether Musical and Slapstick films are eligible for Pollux in the game. If yes, add their genre factors to `POLLUX_GENRE_FACTORS`. If no, add a visible note in the UI that these genres aren't Pollux-eligible.

### 2. `movieScriptIdeas` array in save is not used

The save file contains a `movieScriptIdeas` array (e.g.):
```json
{
  "id": 344,
  "genreID": "DRAMA",
  "settingID": "AMERICAN_CIVIL_WAR",
  "protagonistID": "PROTAGONIST_COWBOY",
  "compatibility": "0.000"
}
```
These are scripts generated by in-game AI characters. The Workshop does not read or display them. This is intentional — the module generates its own suggestions — but a player may not realise their in-game script pipeline is accessible elsewhere.

### 3. Unlock condition fallback when `timePassed` is absent

If `timePassed` is missing or malformed, the module falls back to inferring game date from `tagPool` entry dates. This is a reasonable heuristic but could produce an incorrect date if the player's `tagPool` entries have been edited by this tool (since "Unlock All" stamps them with the current game date). In practice this only affects which elements appear as "available" in the Workshop — no data is written either way.

### 4. `joinedAssociation` field treated as optional

The module uses `saveData?.stateJson?.joinedAssociation ?? false`. If the field is absent (older save format), the "Exclude Banned" toggle defaults to off. This is safe but means players in an alliance on an old-format save won't see banned elements flagged until they toggle it manually.
